# 01 · 美学方向主张

## 一、先定性：这是什么东西

CodeFixer 不是仪表盘，不是 CI，不是 IDE 插件。它是**一台无人值守的修复机床加一本可追溯的账**。

它的核心叙事有三段：

1. **信号进来**——工单从 Redmine / TAPD 流入，系统一直在轮询、一直在听。
2. **机器动手**——双 Agent 反查、修改工作区、验证、复核，全程无人。人只在两个时刻介入：授权开始、处理失败。
3. **账要封存**——Freeze Change 之后修改不可变，patch / hash / verification / review 全部留档，交付是这本账的对外副本。

三段叙事对应三种视觉性格，现在的界面**一种都没做出来**：

| 叙事 | 应有的视觉性格 | 现状 |
|---|---|---|
| 信号进来 | 持续、有节奏、活的 | 静止；空态不显示"轮询正常" |
| 机器动手 | 精密、连续、可追踪 | 8 个带序号的圆点 |
| 账要封存 | 沉、硬、不可撤销 | 和候选状态长得一样 |

`product.css` 顶部的注释已经写对了方向——`an industrial repair ledger`。本评审要做的是把它兑现。

## 二、方向定名：**工业修复账本 / Industrial Repair Ledger**

一句话描述：

> 一台机床的控制面板，和它旁边那本用来记录每次维修的硬壳台账。金属灰的机身、一条橙色的信号线、印刷体的台账页。

不是"科技感"，不是"极简"，不是"暗黑赛博"。是**车间里那种被使用过的、有质感的、可信的工具**。

### 三个具体的意象锚点

施工时如果拿不准某个决定，回到这三个意象：

1. **示波器 / 心电监护**——信号是连续的一条线，不是一串点。有波形、有节律、有停顿。这是 StageRail 的锚点。
2. **老式账本 / 印刷台账**——横线分隔、栏目对齐、等宽数字、页边留白、序号在左侧固定栏。这是列表和表格的锚点。
3. **机床铭牌 / 设备面板**——蚀刻感的小标签、大写字母间距、状态灯、物理开关的分段感。这是控件和标签的锚点。

### 明确排除

- ❌ 紫色 / 蓝紫渐变 / 白底玻璃拟态（`frontend-design` 明确禁止，也和产品无关）
- ❌ 满屏圆角卡片 + 柔和阴影的 SaaS 通用样式（规范 §16 已禁止，现状违反）
- ❌ 拟物化机械纹理、齿轮、扳手图标（"工业感"不靠贴图，靠结构和节奏）
- ❌ 大面积插画空态、吉祥物（这是无人值守的生产工具，不是消费产品）
- ❌ Inter / Roboto / 系统默认字体栈

## 三、五维度态度

### 3.1 Typography · 排版

**主张：一套等宽做骨架，一套人文无衬线做肉，中文单独选。**

| 角色 | 字体 | 理由 |
|---|---|---|
| **显示 / 标题 / 数据** | `IBM Plex Mono` | 等宽 = 台账对齐 = 机器输出。它的斜切终端和方形点比 JetBrains Mono 更"印刷"、比 Space Mono 更克制。用在 h1、指标数字、阶段耗时、ID、hash、路径。 |
| **正文 / 界面** | `IBM Plex Sans` | 与 Plex Mono 同源，度量兼容，中英混排时基线一致。它有明确的工程血统（IBM 为技术文档设计），x-height 适中，小字号清晰。 |
| **中文** | `Noto Sans SC` | 与 Plex Sans 灰度接近，字重轴完整（300–700），远好于微软雅黑的糊。 |

**为什么是 Plex 而不是别的**：
- 同一家族提供 Mono + Sans + 中文兼容度量，一次决策解决全站——本产品几乎每行都是中英混排，度量一致比"更有个性"更重要。
- Plex Mono 用作**标题字体**（不只是代码字体）是一个有态度但不猎奇的选择，直接兑现"机器输出 / 台账"的意象。
- 明确不是 Inter、不是 Space Grotesk（`frontend-design` 点名要避免收敛到它）。

**排版规则（态度）**：
- **等宽只给机器产生的东西**：ID、hash、路径、耗时、计数、状态码、阶段名。人写的文案（工单标题、失败提示、说明）一律 Sans。这条界线要严格——它本身就是信息设计。
- **正文 14px 起，不做 9px**。9/10px 只保留给 mono 的 micro label（例如卡片角标 `01`）。
- **数字全站 `font-variant-numeric: tabular-nums`**（规范 §4.3 已要求，未实现）。轮询每 2–3 秒刷新一次，比例数字会让整列跳动。
- **大写小标签用字距**：`SECTION` 类 kicker 用 `letter-spacing: .16em`，这是铭牌感的来源。
- **中文标题不用负字距**。现在 `h1{letter-spacing:-.045em}` 在中文上产生粘连。拉丁标题可以 `-.02em`，中文归 0。

→ 具体 token 见 [02-foundation.md §1–2](02-foundation.md)。

### 3.2 Color · 色彩

**主张：一条橙色信号线，穿过一片有温度的灰。**

- **保留 `#f4603c` 作为唯一主色**，但给它完整色阶（现在只有 2 级）。它是"信号"，不是"品牌装饰"——**只有正在发生的事才配用橙色**：running 状态、当前阶段节点、活跃导航、主 CTA。静态信息一律不用。
- **底色不做纯白 / 纯黑**。亮色 `#f5f6f4`（微绿暖灰）、暗色 `#0e1110`——现状已经对，保留。这是"车间"而不是"实验室"。
- **状态色是语义不是装饰**，规范 §3.3 的六色体系保留，但要做两件事：
  - `--side`（`#c258a0`，side-effect）**必须启用**。这是本产品最有价值的语义之一——"任务失败了，但 worktree 还在 / MR 已经建了"。现在这个信息用普通灰色 code 块呈现，等于把最需要人注意的东西藏起来了。
  - **暗色单独调值**，不能复用亮色（现状复用，导致 `#36a26b` 在 `#0e1110` 上发闷）。
- **第三方品牌色全部退场**。Redmine `#aa1f2e`、TAPD `#2868d8`、Claude `#d97757`、OpenCode `#4f8b73` 换成**统一的单色字母牌 + 形态区分**（见 [06](06-pages-projects-providers-settings.md) §3）。理由：这是内部工具，用户不需要靠品牌色认平台，需要靠它认"这个来源现在通不通"。
- **主 CTA 用什么色**——现在 `.primary{background:var(--text)}` 是近黑。**改成 `--signal` 橙红**。近黑主按钮是 Vercel/shadcn 的默认，正是"通用 Admin Template"的味道；橙红主按钮才是这个产品的。

→ 具体 token 见 [02-foundation.md §3](02-foundation.md)。

### 3.3 Motion · 动效

**主张：动效只服务两件事——信号在流动、状态发生了转折。其余一律不动。**

现状是 1 个 keyframes + 2 个 transition，等于没有。但方向不是"加很多动画"，是**加对的四个**：

1. **信号脉冲**（`signal 1200–1800ms loop`，规范 §15 已定义）——当前阶段节点缓慢呼吸。这是全站唯一持续运行的动画，它证明"机器还活着"。
2. **轨道流动**（reconciling 状态）——沿 StageRail 边缘慢速行进的光点。规范 §6 已写明"traveling signal"，未实现。只在对账 / 重试交付时出现。
3. **状态转折**（`emphasis 360ms`）——Candidate → Frozen Change 的那一次视觉硬化（规范 §11）。这是全站最重的一次动效，因为它对应产品里最不可撤销的一步。
4. **进入 / 退出**（`standard 220ms` / `exit 140ms`）——抽屉、模态、toast。现在全是硬切。

**明确不做**：滚动视差、逐项 stagger 入场、hover 放大、卡片 3D 倾斜、装饰粒子。这是长时间开着的监控界面，**任何无意义的运动都会变成噪音**。

**必须做的一件小事**：全站 `prefers-reduced-motion` 降级——把 loop 动画换成静态双层描边。

→ 见 [08-motion-theme.md §1](08-motion-theme.md)。

### 3.4 Spatial Composition · 空间

**主张：从"卡片网格"换成"栏目 + 横线 + 左侧信号栏"。**

现状是标准的 12 栅格卡片流——每个东西包一个圆角盒子，盒子排成网格。这是"死板"的结构性来源。

改成：

- **左侧固定信号栏**：列表每行、卡片每张，左侧留一条 3–4px 的固定竖栏，用状态色填充。这既是账本的"页边栏"，也让扫视时**只看最左侧一列就能读出全局状态**。（`.project-ledger-card:before` 已经有这个雏形，但只用了 `--line` 灰色，白白浪费。）
- **横线分隔取代卡片边框**：任务列表、依赖列表、交付 target 列表——全部改成共享容器 + 1px 分隔线。规范 §16 原文就是这么要求的。
- **打破对称**：首页现在是 `1fr / 350px` 的规整两栏。改成**主栏偏左、"需要处理"作为贴边的窄栏**，并让"需要处理"在有内容时**向上侵入指标条的高度**——异常应该在版面上就显得"突出来了"。
- **留白给标题，密度给数据**：page heading 区域大幅增加上下留白（现在 `main{padding:42px 46px}` 内标题几乎贴着内容），数据区反而收紧行距。这个对比本身就是节奏。
- **max-width 分类型**：现在全站 `main{max-width:1580px}`。表格类可以宽，阅读类（失败说明、向导表单）应该 `max-width: 68ch`。现在失败提示在 1580px 宽屏上拉成一整行，可读性差。

→ 见 [02-foundation.md §5](02-foundation.md) 与各页面分册。

### 3.5 Backgrounds & Details · 背景与质感

**主张：不用图片、不用渐变网格，用"印刷缺陷"做质感。**

四个具体手法，全部纯 CSS、零资源、暗色亮色都成立：

1. **极细网格纹理**——`main` 背景叠一层 `repeating-linear-gradient` 生成的 32px 网格，透明度 `.025`。这是工程图纸 / 台账格线的暗示，几乎看不见，但会让大片空白不再是"空"。
2. **噪点覆盖**——一层 SVG `feTurbulence` 生成的 data-URI 噪点，`opacity:.02`，`mix-blend-mode:overlay`。消除纯色平面的"数字塑料感"。这是全站唯一的"贴图"，且是内联的。
3. **顶栏信号线**——`.topbar` 底部那条 1px 边框，改成**左侧一小段橙色 + 右侧灰色**的复合线，橙色段的长度对应"当前活跃任务占比"。一条本来就存在的分隔线顺便变成了数据。
4. **纸张边缘阴影**——抛弃现在的 `0 16px 45px rgba(30,40,33,.08)` 这种柔和大投影（典型 SaaS 卡片阴影）。换成**极短硬阴影 + 1px 实边**的组合，像纸叠在纸上。规范里没写阴影 token，这是 [10-spec-upgrade.md](10-spec-upgrade.md) 的建议项。

**空态要有心跳**——规范 §19 已给出范式：

> 暂无 Bug 任务 / 工单轮询正常 · 上次检查 18 秒前

现状空态只有一句"这里还没有任务"。加上轮询状态后，空态从"坏了吧"变成"在待命"。这是本产品空态设计的关键——**它是无人值守系统，空态是常态，空态必须传达"我在听"。**

## 四、一句话验收标准

改完之后，把界面截图去掉所有文字，只留形与色，应该还能看出来：

- 哪里在动（橙色，唯一）
- 哪些是机器说的话（等宽，左对齐，有格线）
- 哪些是人要做的决定（实心橙钮，唯一）
- 哪些已经封存了（硬边、双线、无动效）

现在的截图做这个测试，只能看出"这是个后台"。
