# CodeFixer 视觉与交互评审归档（2026-08）

本目录记录 CodeFixer 管理界面从首次视觉诊断到形态对齐落地的六轮评审。文档保留历史推理，但不同轮次的结论并不同权；后续轮次可以修正或废止前一轮建议。

## 当前有效结论

优先阅读 [第三轮：单一任务账本](03-single-ledger/15-round3-single-list.md)、[第四轮：设置页方感与卡片对齐](04-alignment/16-round4-settings-alignment.md)、[第五轮：流水线弹窗](05-workbench/18-round5-workbench-fixes.md) 与 [第六轮：反馈源页](06-sources/20-round6-sources-fixes.md)。当前已经确认：

- 删除重复首页，进入系统直接看到唯一任务账本。
- 异常与待授权任务在同一账本置顶，不复制成第二个列表。
- 全局模式、健康和容量属于紧凑状态，不单独占据首页。
- 真机空库、移动端底栏、失败抽屉和视觉快照必须使用真实 API 契约或正式 fixture 验证。
- 设置页不使用左侧彩色竖带做卡片分类；状态色只服务真实状态语义。
- 同一行卡片等高，主控件贴底，形成标题轴与控件轴两条对齐线。
- 四个页面的标题区结构统一为 kicker → h1。
- 已有专属版面（失败、no_change）的任务，不再用通用结论面板兜底复述同一句话。
- 加载态与就绪态必须共用同一套标题区结构，异步请求返回时页面不得发生位移。
- 忙碌态按控件分组，一次保存只锁住正在操作的那一组。
- 健康检查不展示「N/N 项正常」这类不可点开、无从核对的内部计数；正常时只给能力结论与版本号，实现引用只在异常时露出。
- 视觉基线阈值必须小到能测出「删掉一行文字」；`maxDiffPixelRatio` 不高于 0.0005。
- 独立对象（卡片、可折叠区、配置组）必须四边收口；`border-block` 只用于同一张卡内部的分隔。
- 状态色用整圈描边染色表达，不用 3px 彩色左边线。
- 组间距必须明显大于组内间距，否则并列关系会被读成父子关系。
- 层级靠对比维度的数量（字族 / 字距 / 颜色），不靠字号硬堆；密集表单里的分组标题用 10px mono 眉标，不用放大的 sans 标题。
- 分步向导取定高，按最长步骤的**最坏内容组合**实测取值；高度跟随内容会让底栏按钮四档抽动，比留白更难受。内容溢出时必须给出渐隐提示，不能只靠浏览器滚动条。
- 状态色整圈描边只适用于**单个对象**；列表项这种可能同时出现多个的，状态由 soft 底色承载，描边保持环境层级，否则全体异常时整片版面被染色，反而失去「一眼扫到」的作用。
- 类名和实现必须指向同一种对象：叫 `card` 就要有边界，长成表格行就别保留卡的信息密度。
- 不可编辑的**信息展示**不要用 `disabled` 按钮承载 —— 会吃到 `opacity: .46`，把信息压到读不清；改成只读身份条，并把「为什么不能改」讲出来。
- 定高弹窗的底栏用 `margin-top: auto` 吸底，多余空间落在内容与底栏之间，按钮位置才恒定。
- 表单栅格不留孤立空洞：一对字段（账号 / 密码）用整行子栅格并排；分组间隔造成的空格是有意的，字段被拆到对角不是。

最新产品语义以 [产品 SPEC](../../design-spec.md) 为准：主导航进一步收敛为“任务 / 流水线 / 设置”，“项目”和独立“工单来源”不再是一等导航对象。

## 结论冲突时如何处理

1. 产品对象、导航、状态和业务边界以 `docs/design-spec.md` 为准。
2. 页面结构以第三轮为准；元素形态与对齐以第四轮为准；流水线弹窗内部以第五轮为准；反馈源页以第六轮为准。
3. 后一轮未覆盖的问题依次回看前一轮。
4. 历史文档中提到的“首页”“项目”“工单来源”是当时实现的名称，不应据此恢复已废止结构。
5. 评审截图含 mock 数据，只能证明视觉状态；业务字段和流程必须以正式 API、Schema 与 E2E fixture 为准。

## 已明确废止或修正的建议

- 恢复独立首页：废止，任务页是唯一任务列表。
- 首页 StageRail 改紧凑态：废止，真机首页当时并未获得阶段数据。
- 亮色 / 暗色 / 跟随系统三态：废止，只保留亮暗切换。
- 把前端刷新时间称为“工单轮询时间”：废止，除非后端提供真实轮询事实。
- 任务页不设英文 kicker（15 册验收项）：修正为四页反向统一，全部保留 kicker。
- 用左侧彩色竖带区分设置页卡片：废止，状态色不做装饰性借用。
- 将所有第三方品牌色视为违规：修正为收敛到令牌层并限制使用范围。
- 将字号机械限制为恰好五档：修正为语义化字号层级。
- 在设置页展示平台自检计数（「4/4 项核心正常」）：废止，该数字恒为真且不可核对。
- 认为「方感」只存在于设置页：修正为 `border-block` 是全代码库的系统性习惯，第五轮给出按「边界 / 分隔」区分的判定标准。
- 用背景渐变做滚动溢出渐隐：废止，会被卡片自身底色盖住；改用 `mask`。
- 认为「彩色左边条只在设置页和弹窗」：修正为反馈源列表还有一处 4px 的，且因列表壳无左边框而事实上充当整个列表的左边线；第六轮清零。
- 第五轮「状态色一律用整圈描边染色」：修正为只适用于单个对象，列表项改由 soft 底色承载。

## 验证材料

正式视觉 fixture 位于 `frontend/e2e/fixtures/visual-control-tower.json`，Playwright 用例与基线位于 `frontend/e2e/`。一次性审计脚本与截图属于临时复评材料，不是长期事实来源，每轮收尾即清理。

两条常驻纪律：

1. `npm run test:e2e` 打的是 `127.0.0.1:9522` 上已运行实例的 `frontend/dist`，**不是 dev server**。改完前端必须先 `npm run build` 再跑 e2e，否则验的是旧产物。
2. `--update-snapshots` 只重写**失败**的基线。阈值过松时基线会静默滞留在旧图上——第四轮就因此漏更了两轮。收紧阈值前先零容差连跑三次确认渲染确定性，见 [16 册 §7](04-alignment/16-round4-settings-alignment.md)。
